# Rulebook

## Building

1. Solve the whole task with the smallest change that works, and cut everything else.
2. Get a rough version working first, then improve it.
3. A finished entry beats a bigger unfinished one.
4. Never pass off fake data, hardcoded results or stubs as finished work.

## Researching

5. Don't trust memory for anything that changes. Check it.
6. Check the project's own versions first, then official docs. Official docs beat blogs.
7. Confirm a package exists and is maintained before adding it.
8. Research only when it can change a decision, and name your source.

## Judging

9. Everyone scores on one scale: 0 is broken, 5 works with real flaws, 8 is solid, 10 has nothing to fault.
10. Check claims and sources yourself, and never reward a polished summary.
